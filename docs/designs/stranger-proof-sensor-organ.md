## Vision

### 10x Check
Approach B makes snoop trustworthy anywhere; the 10x past that is snoop
**provably right and visibly improving**: identity binding strong enough that
the card explains *why* it's the right person, and a measurement loop where
every real use sharpens probe ordering and grows calibration. The numbers
become the marketing; the marketing regenerates itself. With E1 accepted, this
plan ships that whole arc in one branch.

### Platonic Ideal
You think of a person and type one line. Thirty seconds of sensor time later
you have what a great chief of staff would have prepped: who they are, the one
address that works, the best way in, and a reason to believe every single
line — misses labeled as honestly as hits. It never asks what it can figure
out, never claims what it can't cite, and works identically on your laptop and
a stranger's. Using it makes it better — each week's hit rate is a little
higher than last week's, and it can prove that too.

### Eureka (landscape)
Contact-tool incumbents' stored database is their liability (20–25%/yr decay,
junk inference); an LLM with live typed sensors needs no database for
single-target lookup — freshness and grounding by construction. snoop is
live-sensing vs stored-copy, a different category, not a cheaper Hunter.
Scoped honestly (premise 2 revised after the Codex challenge): this holds for
targets *with a public trail*; for thin-trail targets snoop's value is the
honest blank instead of a stale guess.

## Accepted Scope (this plan = design doc baseline + accepted expansions)

Baseline (Approach B, per the design doc):
- Zero-friction loop: SKILL.md self-plan contract; Google-probe auto-arm logic
  gated behind `--allow-google-account` until the consent flow (M2
  diagnose-first first-run) ships, then ungated.
- Typed degradation contract: sensor_status `ran|skipped|degraded` + reason,
  mapped onto ResolverResult.status (`ok|empty→ran`,
  `timeout|unavailable|error→degraded`, never-invoked→`skipped`, SMTP
  `unprobed`→`skipped`); `--ground` renders "not checked because…" lines.
- First-run flow: diagnose-first on fresh machines; anonymous-GitHub 60 req/hr
  named degradation case; dnspython missing → `skipped: dependency dnspython
  missing`.
- Honest M365 enrichment: getuserrealm.srf NameSpaceType as provider context,
  never a mailbox claim.
- Per-(candidate, source) provenance preserved in structured `data`, plus the
  Milestone 3 provenance audit.
- Windows: distinct `unsupported` diagnose status (vs `missing`).
- Distribution: one-command install with dependency handling (dnspython
  installed or honestly degraded) per the design doc's Distribution Plan —
  in scope for this branch (README + degradation behavior).
- Calibration: fixture to N≥25 real public-trail targets under the provisional
  ground-truth protocol; one supervised live run; measured per-sensor hit
  rates in README.

Expansions accepted this session:
- E1 sensor-yield ledger (local, yield metadata only — never third-party
  data), archetype-aware probe ordering, calibration growth from real use
  (consent-gated), README hit rates regenerable from the ledger.
- E2 rel="me" bidirectional verification + Bluesky domain-handle sensor.
- E3 keys.openpgp.org verified-identity sensor.
- E4 three worked-example archetypes in SKILL.md (founder-with-HN,
  dev-with-GitHub, exec-on-M365), token-offset by trimming.
- E6 shared wall-clock deadline with true cancellation + per-sensor elapsed-ms
  stamped into the bundle.

## Premises (ratified this session; full provenance in the design doc)
1. The product is the Claude-side experience; CLI ergonomics are non-goals.
2. Live sensing beats stored DBs **for public-trail targets**; honest blanks
   elsewhere — and we say so. (Revised per Codex challenge.)
3. Honesty contract: no probe whose failure mode is a confident false
   positive.
4. Safety fences stay: one target per invocation, no bulk, self-published
   under real name only.
5. First-run on a stranger's machine is product scope.
6. Credibility requires measurement (N≥25 live calibration gate).

## Implementation decisions resolved up front (0E)

  `~/.snoop/ledger.jsonl` — outside the repo, no git-accident path — with a
  strict schema (sensor name, status, elapsed ms, outcome class; never target
  names, addresses, or handles) and one honest README sentence acknowledging
  the default-on local file.
- **Bundle schema versioning:** add `"schema": 2` to the bundle so `--ground`
  and the SKILL.md examples can assert the shape they expect.

  floor, `--deadline` flag to tune.
- **rel=me scope v1 (E2):** personal-site ↔ Mastodon / Bluesky / GitHub
  bidirectional links only.
- **Probe-ordering heuristic** (replacing the deleted scorer's `belongs~`
  ghost): non-pattern source > pattern-only, then source count — until the E1
  ledger supersedes it with measured ordering.
- **Design-doc Open Questions 2–4** (consent-UX wording, getuserrealm opt-out
  flag, stranger-machine detection): deliberately left open; resolved during
  implementation at their milestones (M1, M3, M2 respectively).
- **In-branch merge order & honest total:** baseline B (~1 CC-week) + E1
  (4–5 CC-days) + E2/E3/E4/E6 (~2 CC-days) ≈ 2.5–3 CC-weeks on one branch.

  M2 degradation/consent → M3 enrichment/provenance → E2/E3/E6 sensors &
  deadline → E1 ledger last (it consumes E6's timing data and the calibration
  baseline). Each stage lands green before the next starts (WIP commits per
  continuous checkpoint mode).

## Review findings incorporated (Sections 1–10, all user-approved)
- **1A** Ledger writes are best-effort/never-fatal: stderr warning only; card
  and exit code unaffected; `--diagnose` reports ledger health.
- **1B** One `RunRecord` type in lib/schema.py serializes into bundle timing,
  ledger lines, and calibration rows.
- **2A** `--ground` rejects schema-v1 bundles with a named error + "re-run
  --observations" hint.
- **2B** `deadline-exceeded` is a distinct degradation reason from
  sensor-timeout; resolver crash isolation (snoop.py:412) pinned by a
  regression test.
- **3A (+T3)** Shared fetch helper with SSRF guards: private-IP block with
  **pinned-resolved-IP connections** (DNS-rebinding-proof), HTTPS-only, ≤3
  redirects re-checked per hop, **streamed decompressed-size cap** +
  content-type gate (zip-bomb-proof).
- **3B** `_oneline` control-char collapse mandated for all new bundle/card
  text (PGP UIDs, rel=me titles) with marker-forgery tests. (Prior learning
  applied: profile-card-marker-injection, 9/10.)
- **3C** Ledger key-allowlist + value-pattern CI test enforces the
  no-target-data schema (now including `plan_shape`, `mx_class`, date-only
  `ts`).
- **4A** Zero-observation "honest blank" card is a designed, tested empty
  state (shows checked / not-checked / why).
- **4B** Ledger appends are single-write O_APPEND JSONL lines <4KB (atomic by
  construction); reader skips + counts malformed lines.
- **5A** `_employer_match`/`_ORG_SUFFIX_TOKENS` extracted to lib/normalize.py
  **before** E2 lands (verified duplication: gh_search.py:48–64,
  person_resolve.py:85–111).
- **6A** Deadline chaos test (hung resolver: budget held, deadline-exceeded
  reported, other results survive) is E6's acceptance gate.
- **8A** One-line stderr run summary rendered from RunRecords.

## Outside-voice resolutions (Codex plan challenge, all user-decided)

  archetype learning needs only plan-shape booleans + MX class + date-only

- **T2** E6 mechanism reworded honestly: deadline on waits + cancel queued

  the plan no longer claims it can. Same ≤60s contract; 6A unchanged.
- **T5** Calibration fixture privacy: real-person ground truths go ONLY in
  gitignored `calibration_targets.local.json`; the public fixture holds
  EXAMPLE/synthetic rows + explicitly-consented entries; CI asserts this;
  deletion-on-request retention line added to the protocol. README discloses
  that exact numbers reproduce only against local fixtures.
- **T-minor A** README methodology framing: "measured on N targets of these
  classes, on DATE" — measurements, never accuracy claims.
- **T-minor B** M365 NameSpaceType renders visually separate from any address
  (provider context must not read as address validation).
- **T-minor C** Per-sensor evidence-tier table: rel=me, PGP, and Bluesky
  observation classes each get an explicit [+]/[?] tier + reject path for
  partial/stale/colliding identity evidence.
- Rejected/absorbed: "one branch is bad delivery" (merge-order note + WIP
